# Privacy and data protection

The current demonstration keeps typed questions in the open browser page only. It does not send questions to a server, save them in browser storage, create an account or collect analytics. Questions disappear when the page is refreshed or closed. Visitors are asked not to enter names, contact details or personal health information.

Any future service would require privacy requirements to be designed before collecting user information. This document is a planning baseline, not a completed legal assessment.

## Proposed principles

- Explain the service, its limits and any data use in clear, age-appropriate language before a user chooses to continue.
- Collect the minimum information needed for a defined purpose; avoid identity or health details by default.
- Set retention periods, deletion processes, access controls and secure storage before personal data collection.
- Use fictional data in development and demonstrations. Do not publish identifiable user stories, health conversations, photos or minors' information.
- Assess vendors before transmitting any user data outside the service.
- Use aggregated or de-identified analytics only after the method and risks have been reviewed.
- Provide a clear way to stop using the service and seek help from a trusted person or qualified provider.

## Decisions required

The project owner and qualified advisers should determine applicable legal obligations, consent approach for adolescent users, data controller/processor roles, hosting and cross-border transfers, incident response, and whether a data protection impact assessment is required. No user data should be collected for a pilot until these matters and safeguarding controls are approved.
